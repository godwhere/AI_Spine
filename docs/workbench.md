# 本机网页工作台

iSpine 的日常入口是 [本机工作台](http://127.0.0.1:4175)。界面在浏览器运行，资源、回收站、骨架草稿、自建模板和正式生成记录由一个本机后台保存。Chrome 和内置浏览器读取同一份数据；各自的选中项、页面和缩放状态独立。

## 启动与使用

当前 Mac 的 `local.ispine.workbench` 登录启动项自动运行后台。双击项目中的 `启动工作台.command` 可打开页面；原 `启动桌面工作台.command` 保留为兼容入口，也会打开网页。关闭浏览器不会停止后台或删除工程。电脑关机后数据仍保留，再次登录会恢复服务。

运行环境为 Node.js 24，界面由 `pnpm build` 构建到 `dist/client`。其他本机环境可通过 `pnpm workbench` 启动。后台只监听回环地址，不开放公网；同一台电脑使用无需域名或额外服务器。现有美国服务器仍只承担配置的 AI 网关。跨设备或异地访问需要另外设计身份验证、HTTPS 和文件权限，不属于当前本机运行范围。

正式地址固定为 `http://127.0.0.1:4175`。旧的 4173、4180 地址在可用时由同一进程代理到正式服务。Vite 开发页默认使用独立本机工作区；只有显式配置 `ISPINE_BACKEND_ORIGIN=http://127.0.0.1:4175` 才代理正式数据与任务。开发与预览采用严格端口绑定，取得端口后才读取工作区和任务历史；重启先排空旧实例再加载新实例，不让端口冲突或另一预览中断活跃任务。

默认开发端口 5173 的工作区在 `work/development-5173/workspace`，任务历史沿用 `work/generation/jobs`；其他开发端口使用各自的工作区与 `work/generation/development-端口/jobs`。预览工作区在 `work/preview-端口/workspace`，任务在 `work/generation/preview-端口/jobs`。这些目录与正式数据分离，测试与隔离预览另用临时目录和假 AI。

## 数据与恢复

沿用 `~/Library/Application Support/AI Spine`：

| 内容 | 位置 |
| --- | --- |
| 资源、回收站、删除标记、草稿、自建模板 | `workspace/workspace.sqlite` |
| 生成输入、候选和任务记录 | `generation/jobs` |
| 加密连接配置 | `generation/jobs/.connection/connection.json` |
| 原桌面快照与导入冲突备份 | `migration` |
| 后台运行日志 | `logs` |

数据库按原项目、草稿、模板的名称分区，保持生命周期独立。资源列表从独立版本化索引读取摘要，不读取源文件 payload；缩略图按需读取，选中角色时才读取原始文件、替换图片和校准信息。回收站恢复、永久删除确认、ID 删除标记、未修改的临时模板不保存等规则继续保留。

旧浏览器数据库在第一次打开对应来源地址时自动迁入。迁移完成标记属于浏览器，资源本身属于本机后台；清理浏览器缓存不会删除后台工程。原 IndexedDB 名称与内容保留为迁移来源。相同记录不重复导入；同 ID 的不同内容以独立迁入版本保存，不覆盖已有内容。已经移入回收站或永久删除的项目不会因旧浏览器重新迁移而复活。服务不可用时明确报告保存失败，不自动改存到另一份浏览器数据库。

资源与草稿使用版本检查，避免两个浏览器编辑时静默覆盖较新的版本。资源库定期检查数据版本，其他入口保存后会刷新列表；正在编辑的内容不会被后台更新直接替换。

旧桌面完整备份保存在 `~/Library/Application Support/iSpine Backups/20261020-211941-before-web`。迁移核对覆盖 20 条原始记录，包括 4 个资源、1 个回收站项目、7 个 ID 删除标记、3 份草稿及 1 个自建模板。随后浏览器迁入了原本独立的花杖少女制作稿，合并库中为 5 个正常资源。既有 53 条开发/预览历史记录另行复制到正式生成历史；原目录保留。

2026-10-21 已完成工作区格式 2 激活，保留 4 个正常资源、2 个回收站资源、7 个 ID 删除标记、3 份草稿和 1 个自建模板，身份与作者 revision 保持。完整数据与旧构建备份位于 `~/Library/Application Support/iSpine Backups/20261021-041242-before-workspace-v2`，共 1183 个数据文件核对通过。重启保留所选 Sub2API 和已保存密文；按原规则保持锁定，只有显式连接验证或实际生成才解锁。

迁移与导出备份独立于回收站操作。携带工程到其他电脑时仍使用可编辑 ZIP；备份整个工作台时应先停止后台，再复制用户数据目录，或使用 SQLite 的一致性备份机制，不能只复制运行中的数据库主文件而忽略 WAL。

## 摘要索引维护

新服务首次打开旧库时，在事务中回填索引；损坏记录明确报告，不丢弃或伪造为空资源。摘要以当前激活的格式 2 文档和素材为数据依据。需要检查时，`pnpm index:workspace <workspace目录> --check` 只读对照摘要和原记录；`--rebuild` 从原记录重建派生摘要与缩略图，不改数据库身份或作者修订。路径必须显式给出，工具不会创建缺失的数据库。重建会占用写事务，应在编辑保存完成后进行。正式服务已激活格式 2；摘要检查和重建会自动选择当前格式。

## 保存与离页

普通工程和骨架草稿共用串行保存调度，分别使用自己的记录、版本和入库规则。普通工程防抖 850ms，草稿 400ms；同一实体一次只提交一个快照，写入期间的连续编辑合并为最新内容。只有最新内容收到保存回执后才显示已保存。预览、缩放和缩略图不增加作者内容修订。

返回资源库、切换模板和进入骨架编辑会等待当前写入排空；等待导航时暂时阻止新的编辑。浏览器隐藏时提早保存，刷新或关闭时若仍有待写、在途或失败内容，会保留离页提示。浏览器强制退出、系统崩溃或未确认的网络提交仍不能保证完成。

每次打开编辑器都有独立的基础版本。其他页面已经保存新版本时，旧页面的提交会被拒绝，本地内容继续保留；可通过“另存为新资源”保留这份修改，或导出工程备份。回收站和永久删除标记始终拒绝迟到保存。保存成功后再撤销到模板初始内容，也不会删除已保存资源。

原格式丢失回执时先读取后台核对作者内容，不能确认的新建不会无条件重发。格式 2 已实现稳定保存标识与二进制素材分离，未知提交先核对原回执再写较新内容，未变素材不重复上传；生产副本迁移与反向转换已验证，正式服务已在完整备份后激活格式 2。两种路径失败时均保留本地修改，可重试或导出备份。维护期间可浏览已保存资源，保存明确报错并保留当前编辑；新浏览器的首次旧库迁入会延后，维护结束后继续。操作与回退边界见[工作区协议](workspace-v2-protocol.md#检查点迁移与维护)。

## AI 连接与密钥

继续明确选择 Codex、OpenAI 或 Sub2API，失败不切换服务。macOS 本机后台使用钥匙串保护的主密钥加密保存 API Key。启动、查看连接和浏览资源不读取钥匙串；只有显式验证、保存或实际 API 生成才加解密。缺少系统保护时仅保留本次进程内的 Key，不写明文文件。旧桌面密文在无法解锁时保留。

本次迁移没有发起图片请求或自动续做失败任务。Sub2API 的并发配置、网页生图上游 503/500 和图片质量验收均是独立事项。

## 验证

`pnpm test:workspace` 检查独立客户端、重启持久化、原图字节、版本冲突、回收站、迁移幂等性、冲突保留、请求来源限制和延迟密钥解锁。迁移记录位于 `outputs/desktop/evidence/shared-workspace-migration.json` 与 `shared-workspace-job-migration.json`。其他资源、骨架、动画和导出规则仍由原有测试覆盖。


## 架构调整后的安装与恢复

当前网页及本机后台已完成 P0–P7 架构调整并安装。保存使用格式 2，历史数据名称、迁入来源和删除标记保持。完整最终备份位于 `~/Library/Application Support/iSpine Backups/20261021-053038-architecture-complete`，包含持久数据、旧构建、源代码与 SQLite 一致性快照；原迁移前备份也保留。当前内容有新编辑时，应先备份当前数据，再按版本化维护流程反向转换，不能直接覆盖成旧库。

最终回归、性能限制与正式预览见 [P7 验收](evidence/architecture-p7/acceptance.md)。重启不会自动解锁保存的 API/网关密钥；实际使用仍从 AI 连接入口明确验证或发起生成。
