# iSpine 架构调整执行计划

状态：计划已编写，P0 至 P7 尚未执行。日期：2026-10-20。

目标边界见[架构调整方案](architecture-plan.md)。本计划按一次只改变一类核心边界安排提交，前一阶段通过后再进入后一阶段。用户本轮选择仅交付方案，业务代码和正式数据均不在本轮修改范围内。

## 执行基线

- 当前工作区在 `main`，存在大量已有修改和未跟踪文件。实施前记录实际内容基线；不能用 `git reset`、清理目录或只检查 `git diff HEAD` 来隔离本次修改。
- 上一轮架构评估中，使用项目启动脚本选用的 Node 运行主测试集，结果为 458/458。该数字不包含单独的 desktop、Sites、Python 测试或浏览器完整验收，实施前需要重新测量。
- 当前终端默认 `node` 是应用包装器，曾阻止原生模块加载。实施时先确认 `process.execPath`、Node 24 和原生 Canvas 能力，使用 `启动工作台.command` 中有效的 Node 路径。
- 正式工作台已有本机服务。测试、性能测量与迁移演练必须使用独立目录和端口；普通 Vite 开发入口目前默认代理正式服务。
- 保留全部角色原图、研究稿、已接受动作、生产生成记录、历史 profile 和 IndexedDB 迁移来源。

## 阶段依赖与工作量

工作量按一名熟悉当前项目的开发者估算，包含对应自动化验证，合计约 13–21 人日。大数据迁移演练和外部 AI 服务等待可能增加时间。阶段完成以验收条件为准，不以日期或文件数量为准。

| 阶段 | 产物 | 前置 | 估算 |
| --- | --- | --- | --- |
| P0 | 可重复基线、隔离测试环境、依赖检查框架 | 无 | 0.5–1 日 |
| P1 | 普通工程与 rig 共用保存调度机制 | P0 | 1.5–2.5 日 |
| P2 | 共享数据规则、平台无关计算引擎 | P1 | 2–3 日 |
| P3 | 前端功能边界、后台入口与适配层 | P2 | 2–3 日 |
| P4 | 无大图片读取的资源摘要查询 | P3 | 1–2 日 |
| P5 | 二进制素材分离、版本化传输与可回退迁移 | P4 | 3–5 日 |
| P6 | 任务基础机制与 AI 能力端口整理 | P3；按交付顺序在 P5 后进行 | 1.5–2.5 日 |
| P7 | 完整回归、性能对比和文档收口 | P4、P5、P6 | 1–2 日 |

建议每阶段作为一个可独立复核的变更单元，大阶段进一步按下面的步骤拆分。P1、P4 分别可形成独立的可靠性和性能交付，不必等待所有目录迁移完成。

## P0 建立基线与隔离环境

允许修改：测试工具、架构检查脚本、测试配置、`package.json` 及选定包管理器的锁文件、验证文档。必要时仅为测试暴露服务组装参数。

不修改：保存业务、原始资源、数据库 schema、provider 路由、页面布局。

执行步骤：

1. 记录代码内容 hash、运行版本、已有脏文件、受保护打包文件和当前目录依赖图。已有未提交功能仍是有效基线。
2. 建立测试启动器：独立临时数据目录、系统分配端口、假 AI provider、确定性 fixture、完整的服务清理。测试目标不得默认为 4175。
3. 增加真实浏览器测试基础设施，计划使用 Playwright；浏览器运行与项目测试均在隔离服务中完成。新增依赖只服务于测试。
4. 建立依赖图检查，识别 import、export-from 和可静态解析的动态 import；现有反向依赖先登记逐文件例外，禁止新增例外。
5. 跑主测试与相关现有集，记录导出样本、存储字节、必要的界面截图。保存/切页缺口作为 P1 待修场景，不伪装为通过项。
6. 将日志放在临时目录，验证摘要放在 `docs/validation.md` 或专门证据目录；不将密钥、用户数据库或生成输入写入测试 fixture。

验收：

- [ ] 新启动器与正式数据目录、生成目录没有重叠。
- [ ] 同时运行两个隔离实例不会中断彼此任务。
- [ ] 原主测试保持通过，新增基线能定位失败所属层。
- [ ] 架构例外清单给出当前来源文件、目标文件及负责消除的阶段。

回退：撤回新增测试配置和启动器，不改变生产数据。

## P1 统一保存与会话生命周期

允许修改：`src/App.jsx` 的保存/导航逻辑、`src/core/rig-draft-writer.js`、`src/core/rig-drafts.js` 的版本桥接、新 `src/application/save-coordinator.js` 和必要会话模块、相关测试与文档。

不修改：SQLite schema、HTTP URL、生成内容、导出格式、校准算法和页面布局。现有 `shouldPersistProject` 继续作为保存政策。

执行步骤：

1. 从现有 rig writer 提取通用串行调度能力。普通工程与草稿使用不同 repository/policy；不将二者合并为一种记录。
2. 为普通编辑与 rig 编辑建立固定 session key，明确本地内容修订和服务器基础版本。
3. 接入自动保存、保存按钮、导出后保存、资源/模板导航、进入 rig 及历史桌面关闭入口。
4. 移除保存函数对 `document.querySelector` 的依赖，改由预览组件提供缩略图能力。缩略图变化继续不算作者内容变化。
5. 在 app shell 统一挂接离页保护；写入失败保留快照和错误，用户重试沿用原会话归属。
6. 过渡期使用现有 `expectedUpdatedAt`。无回执时读取并核对服务器记录；不做无条件重发或自动覆盖。

必须验证：

| 场景 | 预期 |
| --- | --- |
| A 写入尚未完成时产生 B、C 编辑 | A 后只需提交最新 C；状态保持待保存直到 C 提交 |
| 自动保存同时触发导航保存 | 同一写入序列，导航等待完成 |
| 保存失败后切换会话 | 原内容仍待恢复；旧回调不更新新页面 |
| 两个浏览器同时修改 | 后写旧版本被拒绝，本地修改仍可另存 |
| 同一浏览器的两个会话指向同一资源 | 各自基础版本独立，不能因共享写队列而绕过冲突 |
| 保存结果丢失 | 能核对已提交内容；不能覆盖其他客户端的新版本 |
| 资源被移入回收站或永久删除后收到旧保存 | 拒绝恢复或重建该资源 |
| 未编辑模板只预览、开关 AI 面板 | 不创建普通资源 |
| 保存后撤销回初始内容 | 资源仍存在 |
| 待写时关闭或刷新 | 提前 flush，并在未确认完成时保留离页提示 |
| 只有原图的 rig 草稿、已关联资源的旧草稿 | 分别保留独立草稿和既有归属/另存规则 |

验收：上述单元/集成测试和真实浏览器导航流程通过；现有主测试通过；不以强制退出后的未知网络完成情况冒充可靠保存。

回退：保留当前数据格式，按本阶段差异恢复保存接线；不删除此前保存的工程或草稿。P1 结束时更新工作台保存说明。

## P2 抽出共享规则与计算引擎

允许修改：`shared/`、新 `engine/`、方案迁移表中涉及的 `src/core` 模块、`src/spine/runtime.js` 的纯解析部分、后台相关 import 和测试 import。

不修改：数据库结构、provider 行为、动作算法语义、艺术数据、界面布局。

执行步骤：

1. 移出工程作者内容比较、临时保存政策、source-only 草稿校验、归属规则和模板元数据规则。
2. 从 `rig-client.js` 移出几何投影、附件组、文档命令与候选匹配；前后端共同引用几何和指纹原料。
3. 将两处 SHA-256 实现归并到纯 codec。保留每类现有指纹的原料、顺序和输出；旧任务没有算法版本字段时按 V1 解释。
4. 分离 archive 的纯处理与浏览器 File/fetch；分离 Spine 数据解析与 WebGL 场景。
5. 将权重、IK、采样、检查、编译、Atlas 以及图片校准算法移动到 engine，明确注入 PixelPort。
6. 后台模板校验改用 engine，摘要与数据校验改用 shared，清除 `server → src` 依赖。
7. 每组迁移保留旧路径转发，更新消费者后移除。新代码不得再反向导入旧兼容层。

验收：

- [ ] shared 导入时不触发网络、存储或平台 API。
- [ ] engine 在无 DOM 的 Node 环境和浏览器适配环境均能测试。
- [ ] 既有指纹样本保持一致；旧任务/候选仍能校验。
- [ ] 骨架关键帧、权重、脚锁释放边界和动作采样结果保持一致。
- [ ] ZIP 条目、图片 hash、作者元数据和附件切换保持；允许的打包时间等非语义差异单独说明。
- [ ] 后台不再引用 `src/`；该类依赖检查例外清零。

回退：按函数迁移提交逆向恢复 import 和实现位置；数据格式不受影响。禁止在同一提交顺带修正动作、美术或导出数值。

## P3 整理功能界面与运行入口

允许修改：`src/app`、`src/application`、`src/features`、`src/infrastructure`、原组件及其 import、`server/bootstrap`、`server/http`、`desktop/server.mjs`、Vite 接线和启动脚本。

不修改：布局样式、素材、数据库 schema、provider 选择政策、受保护的 Sites 文件。

执行步骤：

1. 引入唯一的服务组装入口，显式传入存储模式、API 地址、仓储、预览和 Worker 能力。
2. 按资源库、编辑器、骨架工作台、生成、连接设置迁移 UI；每次只迁移一个功能。
3. 把导入导出、加入模板、候选应用和普通资源保存作为应用用例；界面只提交命令并显示结果。
4. 骨架工作台拆分结构、部件、绑定、动作和验证面板。会话持有文档；面板不各自复制整份文档。
5. 保留播放时钟和相机的独立运行时状态；切换动作不重置同一皮肤的取景或手动缩放。
6. 将静态 HTTP 服务与安全中间件放到 server；desktop 兼容入口反向调用 server。
7. 正式、开发、预览和测试分别组装服务。测试与独立预览拥有自己的 workspace 和 jobs；正常开发代理仍由显式配置决定。
8. 清理迁移兼容层；结构由依赖检查和职责验证验收，不设任意行数指标。

验收：

- [ ] `App.jsx`/AppShell 不再实现存储请求、图像算法或任务业务。
- [ ] 应用层不依赖 JSX、DOM 查询或具体 HTTP 仓储。
- [ ] 原三栏布局、模板一列/三列、资源库列表/网格、窄屏导航保持。
- [ ] 手动部件移动、关节拖动、相机移动各自行为正确。
- [ ] 正式服务故障时明确失败，未写入另一份浏览器数据库。
- [ ] 浏览器后台不依赖 desktop；旧启动入口仍可工作。
- [ ] 主测试、相关 desktop 兼容测试、隔离浏览器流程及构建通过。

回退：按单个功能恢复入口连接；不回退用户数据。完成后更新 README 的已实现目录描述。

## P4 建立独立资源摘要查询

允许修改：`server/workspace`、workspace service、摘要返回契约及对应客户端缓存、迁移与性能测试。

不修改：素材保存格式、导出格式、任务历史和 UI 设计。

执行步骤：

1. 为现有 SQLite 增加版本化摘要索引及可重入回填步骤。
2. 把保存、迁移、回收站、恢复和永久删除的摘要更新加入原事务。
3. 列表查询改读摘要；打开具体资源时才取完整 payload。
4. 区分只读调用和写事务；保证 revision 只反映实际变更。
5. 增加一致性检查和从原 payload 重建摘要的操作，不在每次列表时临时重建。

验收：

- [ ] 摘要请求不读取 `records.payload`，不反序列化源文件。
- [ ] 事务中断时摘要与原记录同时提交或同时回滚。
- [ ] 回填两次结果一致；损坏记录不会被默默跳过。
- [ ] 10、100、500 个资源规模下的列表测量完成。
- [ ] resource、trash、删除标记和模板/草稿行为保持。

回退：停止使用新增索引，恢复原查询即可；索引保留或重建，不删除原记录。

## P5 分离图片数据与版本化保存

允许修改：workspace V2 表和迁移器、素材仓储、V2 HTTP 路由、前端仓储适配、保存回执处理、测试和操作文档。

不修改：角色图像、作者文档与 ZIP 格式版本、资源 ID、旧 IndexedDB、生成任务目录和独立导出文件。

按四个可复核步骤执行：

1. **仓储实现**：在临时库实现 `documents_v2`、素材引用、原始 BLOB、mutation 回执和上传租约。先用合成数据验证事务、去重与删除。
2. **传输实现**：新增能力协商、素材查询/上传/读取与小文档保存。对缺失 hash、伪造 hash、错误预期版本、PUT 跨来源和超限请求逐一验证。
3. **副本迁移**：用一致性副本迁移旧 records，核对所有 namespace、删除标记、元数据、图片 hash 和导出回导；测试各检查点中断重启与反向转换。
4. **正式切换准备与实施**：执行维护、备份、迁移、验证、激活流程。该步骤属于未来实现阶段，本轮不执行。若存在活跃生成或未保存编辑，先协调其完成或明确暂停。

验收：

- [ ] 原始 PNG、骨架、Atlas 和未知保留字段在往返后无损。
- [ ] 已上传素材在校准、改名和关键帧编辑时不重复发送。
- [ ] 响应失落后，同 mutation ID 重试不会形成第二次提交或新资源。
- [ ] 同 ID、不同 mutation 内容被拒绝；墓碑始终优先于迟到写入。
- [ ] 未提交上传可回收，活跃租约和任何独立实体引用不能被回收。
- [ ] 删除原资源不影响其自建模板、草稿或独立生成历史。
- [ ] 老客户端安全读取或收到明确刷新要求，不能继续写旧存储分支。
- [ ] 旧浏览器再次迁入不会复活已删除资源。
- [ ] 新格式激活后产生的新编辑可在回退演练中保留。

回退分界：激活前使用旧结构；激活后先停写并备份当前数据，再反向转换或使用兼容 V2 的程序。仅恢复迁移前备份会丢掉新写入，禁止作为默认回退。

## P6 整理任务调度与 AI 能力

允许修改：GenerationJobs/RigJobs、jobs 基础组件、AIConnections 接线、provider 契约、Codex RPC 接线、相关测试与连接文档。

不修改：用户当前连接、上游账户和网关配置、图片协议选择、任务文件身份、提示词内容和候选应用政策。

执行步骤：

1. 抽取原子 manifest 写入、加载、状态转换、任务取消和关闭排空；先保持已有队列行为。
2. 将模板形象/部件、rig 形象/补绘、结构规划和动作研究分别接入 handler。
3. image 与 planning 能力分开声明。结构化规划仍只走用户明确选择的 Codex 路径，不因图像 provider 改变而自动切换。
4. 连接配置和密钥解锁留在连接服务；provider 适配器只处理对应协议。
5. 验证任务创建、失败、取消、重试和服务关闭时，所有在途请求和 manifest 写入均有明确归属。
6. 若引入共享并发预算，先记录现状并明确新增限制，不能将两个独立的“4 并发”误当作整个进程“4 并发”。

验收：

- [ ] 三种图像 provider 的假服务契约测试保持通过。
- [ ] 重试固定 provider、model、endpoint 和 part 映射；只补未完成项。
- [ ] 取消覆盖所有在途 turn，关闭等待任务收尾和持久化完成。
- [ ] 重启不自动恢复生成，不改写其他服务实例的活跃任务。
- [ ] 启动、浏览连接设置不解锁密钥；错误不泄露凭据。
- [ ] 完整角色验收仍独立于单个部件生成成功。

回退：恢复原任务编排实现和接线，保留任务 ID、图片和兼容的 manifest；不能为代码回退删除任务历史或重新运行生成。

## P7 最终验收与文档收口

允许修改：测试、证据、文档，以及验收发现且属于重构范围的局部缺陷。新增业务需求另列任务。

执行步骤：

1. 依赖检查例外清零；移除已无消费者的转发层。旧格式读取器和必要兼容入口仍保留。
2. 执行完整回归、浏览器流程、性能测试和迁移/回退演练。
3. 更新 README 当前目录和技术组成；更新 workbench、generation、ai-connections、rig-authoring、validation 中受影响的内容。
4. 执行构建和 Sites 打包检查，确认 `dist/client/index.html`、`dist/server/index.js`、`dist/.openai/hosting.json` 仍存在。
5. 在独立构建目录验收，避免构建过程半途覆盖正在使用的生产静态文件。正式替换时使用完整产物切换。
6. 比较基线与最终差异，确认受保护文件、用户素材和无关工作未被覆盖；记录仍需真实外部服务或人工美术检查的边界。

完成条件：下列矩阵全部有结果或明确的外部验收状态，不能把跳过项计为通过。

## 验证矩阵

| 范围 | 现有基础 | 新增重点 |
| --- | --- | --- |
| 保存 | `storage`、`project-draft`、`rig-draft-writer`、`rig-draft-lifecycle` | 普通工程串行保存、乱序响应、刷新/导航、失去回执 |
| 数据 | `workspace`、`custom-templates` | 摘要索引、资产引用、V2 迁移、崩溃点与反向转换 |
| 编辑 | `rig-workbench`、`rig-canvas-adjustment`、`rig-part-adjustment` | 真实 React 状态生命周期、拖动撤销、跨页面会话 |
| 图像与骨架 | `pixels`、`runtime`、`rig-authoring`、`rig-registration` 等 | 抽取前后像素、采样、约束释放和附件规则等价 |
| 导出 | `core`、`template-variants`、`unity-export`、`rig-project` | 浏览器实际下载 runtime/editable ZIP 并重新导入 |
| AI | `generation`、`rig-service`、`sub2api`、`ai-connections` 等 | 多队列并发、任务关停、重试身份、无自动 fallback |
| 交付 | `test:desktop`、`test:sites` 及相关 Python 测试 | 浏览器入口不依赖桌面、隔离数据根、产物路径保持 |
| 架构 | P0 新增检查 | 禁止依赖、平台全局访问、临时例外与循环依赖 |

建议增加 `test:architecture`、`test:e2e`、`test:performance` 三个入口。现有 `test` 保持确定性和无需真实账号；真实 AI 请求单独标记，不计入普通回归。

### 浏览器最小验收集

1. 打开模板并预览多个动作，返回资源库，没有新增资源。
2. 修改名称和校准，立即导航；重新打开时内容与确认保存的版本相同。
3. 保存进行中继续编辑，最终状态对应最新修改；刷新后复核。
4. 两个页面同时编辑同一资源，旧版本不能覆盖新版本，另存可保留本地内容。
5. 将资源移入回收站，验证旧页面保存被拒绝；恢复后再编辑。
6. 在隔离测试库中经明确确认永久删除，旧缓存迁移和迟到保存均不能复活资源。
7. 保存 source-only 草稿，重启隔离后台后恢复；未完成 rig 不出现在普通资源库。
8. 将完成资源加入模板，再修改/删除原资源，自建模板仍可打开。
9. 使用假 provider 产生候选，取消不应用；跨资源或过期几何应用被拒绝。
10. 下载 runtime、editable 和 Unity 包，重新导入并检查全部动作、附件和必要作者数据。
11. 相同皮肤切换动作，保持相机和手动缩放；部件拖动不改变相机或原图字节。

每个用例输出操作结果、必要截图与下载包检查摘要。截图只能证明画面；持久化通过数据库/API 和重新打开共同证明。

### 性能验收

样本使用固定种子的合成工程，覆盖 10、100、500 条资源及 1 MiB、10 MiB、50 MiB 的单资源素材规模。采用代表性组合而非全量笛卡尔积，避免无意义地生成数十 GiB 数据。

| 指标 | 验收要求 |
| --- | --- |
| 列表资源读取 | P4 起不读取源文件 payload/BLOB；返回摘要不含 files、edits、生成原图 |
| 列表延迟 | 相同机器和数据，冷启动单列；预热后至少 30 次测量 p50/p95。500 条摘要 p95 暂定目标 200ms，P0 基线后确认 |
| 校准保存 | P5 起未变化素材上传量为 0；仅一个变换修改的提交体暂定目标小于 64 KiB，不含首次上传和预览图片 |
| 后台响应 | 大素材上传期间记录 status 请求延迟和事件循环延迟；确认图片编码/数据库操作是否需要进一步移到 Worker |
| 存储体积 | 比较真实唯一素材字节与数据库增量，核对去重与无引用回收；不以数据库文件大小直接等同磁盘即时回收 |
| 前台交互 | 记录重图像操作长任务；必要时逐项迁入 Worker，不能一次移动全部算法后再定位回归 |

耗时阈值是拟定预算，并非已测结论。若不达标，先定位耗时来源；增设 DB Worker、缓存或额外服务需要对应测量支持。
