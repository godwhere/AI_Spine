# 新骨架与动作

这条流程用于从 Q 版人形战斗角色立绘制作独立骨架。AI 负责分析结构、补绘部件和提出关键姿势；程序负责坐标、骨长、绑定、约束计算和 Spine 格式。已有模板制作流程继续保留。

## 操作流程

1. 在「我的资源」点击「新建角色」，选择从立绘新建或继续本机草稿。导入 PNG、JPEG 或 WebP；画布坐标向右、向下，较大立绘会按比例缩小。
2. 若导入的是普通立绘，先在「参考图转 Q 版形象」填写风格、服装和武器要求，点击「生成 Q 版形象」。检查透明背景、完整四肢和握持关系后，明确确认候选。已有骨架时，应用新形象会再次确认重建；取消会保留当前骨架。已有合适 Q 版图可直接跳过此项。然后点击「AI 结构分析」，检查候选中的关节、部件矩形、绑定骨和遮挡层级，确认后应用。也可以明确选择「程序人形初稿」手工起步；它不会被标记为 AI 识别结果。
3. 在叠图上拖动关节，或编辑坐标和父级。按源图调整每个部件的矩形与前后顺序；原图裁片仅供校对，仍显示为待补绘。
4. 选中需要补绘的部件，提交 AI 透明图片生成，或逐件上传独立透明图片。默认同时生成 3 个，可选择 1–4 个。候选不会自动覆盖；检查后明确应用。隐藏的肢体表面和连接处需要补画，普通矩形裁切不会被当作已完成部件。
5. 在拆分或绑定步骤选择「校准部件图片」，按立绘裁片参考调整独立图的平移、缩放、旋转与镜像，也可自动适配透明轮廓。取消保留原图，应用会烘焙图片；关节、部件矩形、权重和动作保留。裁片与占位图不能靠校准变成已补绘部件，透明背景和可见内容都必须通过检查。为硬质部件选择刚性绑定，为衣物、身体或头发选择加权网格，可调整 2–8 行列的密度、影响骨与逐顶点权重；武器可设置主手握点及可选副手握点。
6. 在动作步骤制作待机、攻击和受击，也可添加其他动作。填写动作描述，AI 生成该动作的关键姿势；确认应用后，可以调整时间、角度、骨骼局部位移与缩放、根位移、绘制顺序、插值和脚锁。修改描述后重新生成，只替换同 ID 动作，保留骨架、图片、网格与其他动作。
7. 更新真实动画预览，检查姿态、遮挡、接缝和动作节奏。检查报告会列出脚锁误差、武器握点误差及循环首尾差异。不可达目标需要修正关节、握点或关键帧，不能靠标记完成跳过。
8. 全部部件具有独立图片、所有动作通过检查后，点击「保存为角色资源」。随后使用普通编辑器校准、导出运行时 ZIP、Unity 资源或可编辑工程。资源详情与编辑器中的「骨架与动作」可返回继续修改。

结构分析的「部件精细度」默认精细，目标 24–40 个、最多 64 个部件；标准档使用 12–18 个部件。拆分依据实际活动边界，手掌与前臂、上下肢、发束、衣摆和武器分别拥有可用的绑定。选择档位不会重建当前草稿，新的结构候选仍需确认。纹理区域数与骨骼数不同；不同手形、表情及朝向切面需要附件切换，不作为同时显示的叠加图层。

补绘任务保留原生 PNG 与尺寸，逻辑部件图采用等比适配并留透明边距。应用候选同时核对源图指纹、几何快照和部件 ID；已应用后经过校准的同一候选不会被重复覆盖。失败或取消时可先应用成功图片，再选择「继续未完成」和并发数量；续做固定使用原任务的参考、说明、服务与模型，仅补缺失部件。

### 手动调整部件

资源详情和普通编辑器中的「手动调整」可直接打开包含骨架编辑数据的资源；独立骨架工作台的画布工具栏也提供同一入口。此模式暂停动画、显示基准姿势和完整部件组合，关节拖动与部件移动分开。先从左侧选中部件，再拖动金色手柄；方向键每次移动 1 像素，Shift 加方向键移动 10 像素。右侧可输入精确 X/Y、按中心等比缩放和调整前后层级。每次完整拖动只占一条撤销记录，Esc 或取消指针操作可撤回本次拖动。

移动会调整部件相对骨架的基准位置，连续骨骼动作使用新的位置；不会重画或裁切原始 PNG，也不会改关节、动作关键帧和已有网格权重。尚未固化的自动权重在第一次调整前固定为当前有效权重。仅独立图片可移动，源图裁片和占位需先补绘；超出画布的调整明确拒绝。源像素轮廓、注册底图和历史测量保持来源坐标，旧测量标记为历史。移动武器后需检查握点，不能将数值有效视为握持验收。

选择隐藏表情附件会临时显示该附件供调整，保留组默认设置。修改先自动保存在独立草稿，使用「更新动画预览」检查所有动作，再按既有检查流程保存为角色资源。网页与可选 App 外壳使用同一套操作；已经保存的资源和草稿保留，不提供发送到 App 的入口。

### 原图坐标对齐

独立补绘可能改变衣服、腿和头发的轮廓，透明留白也会影响放入矩形后的实际尺寸。等比适配只保留生成图自身的比例，不能保证与原角色一致。在拆分或绑定步骤使用原图坐标对齐，将已确认的 Q 版图固定为像素坐标基准；网格、关节、部件矩形与轮廓使用同一坐标。

坐标规划通过 Codex 结构化输出提出默认可见部件的多边形，候选不会自动覆盖草稿。先检查轮廓和部件对应关系，再检查对齐效果。矩形容纳不下原图轮廓时，明确扩展边界：旧图片按原位置补透明边距，保留比例、关节、逐顶点权重和动作。应用为一次可撤销的修改，过期来源或已变动的几何不能直接覆盖当前草稿。

原图可能在主体外留有接近透明的零散像素。显式扩框可将这类像素保留在邻近刚性部件的透明边距中，记录归属及扩框范围，避免为背景边缘移动加权网格。若主体轮廓本身要求扩大网格部件的矩形，规则网格的取样范围也会改变；保留权重数值后仍需复查弯曲效果。

对齐要求所有默认可见部件已有完成的独立图片，拒绝原图裁片、占位图和完全透明的空图。可见原图像素分配给当前默认附件，每个像素只归属一个部件；已有独立补绘图片用于被前层部件遮挡的内部表面。默认眼、眉、嘴分别提取到自己的显示组，其他表情按同组原图范围对齐。脸部底片需事先补绘为无眼、眉、嘴的完整皮肤，避免切换表情时出现重影。报告显示未覆盖与额外轮廓、重叠面积比、颜色及透明度误差，以及需要按距离回填的像素；数值正确仍需要检查部件活动时的接缝与遮挡。半透明边缘经过图层合成可能存在少量舍入误差，按实际测量显示。

隐藏补绘只保留在原图接近不透明的内部区域，Alpha 门槛为 250/255，并避开外缘一像素。不能只接受 Alpha 254 或 255：部分生成图的眼睛内部是 252–253，这会误删切换闭眼时需要露出的皮肤。默认图层仍保留原始可见像素；下方隐藏层会使近不透明区域最多增加原图剩余的透明度，按每像素实际预算检查和显示。源图与柔和外缘不会被统一改成不透明。

首次对齐前的独立补绘图和原矩形作为稳定底图保存。随后拖动轮廓并重新对齐，继续从这个底图补隐藏表面；不会把上一次锁定的原图像素误当成 AI 补绘。底图随工程以独立文件归档，重新上传、应用新候选或手动校准后会刷新来源。空部件即使总体叠图相似，也不能通过检查。

轮廓、网格尺寸、源图指纹、坐标任务来源及验收数值随作者工程保存，原生 AI 图片与任务记录继续保留，便于追溯重画和缩放的影响。报告记录应用时的实际组装；随后修改图片、矩形、层级、默认附件或原图，应重新检查，不能把历史数值当作当前状态通过。

### 动作预设

动作步骤的「新动作预设」提供跑步、技能、死亡、胜利和自定义，首次对应 `run`、`skill`、`death`、`victory` 等可读 ID，重复添加使用数字后缀。预设只建立待制作槽，仍需生成或编辑关键帧并检查。跑步的腾空与死亡倒下可按实际接触状态解除脚锁，着地阶段再设置锁定；检查报告需要结合动作意图和画面判断。

脚锁标志按关键帧离散切换，重心在帧间连续插值。起跳帧应先解除脚锁，再开始向上位移；等到腾空峰值才解除，会让此前仍锁定的腿出现不可达误差。落地帧再恢复接触约束，并检查该阶段的真实采样数。

骨架工作台按动作的循环选项播放。非循环动作到末尾暂停，时间条和真实 Spine 预览保留最后姿态及附件；再次播放从起点开始。循环动作继续首尾衔接，切换动作沿用同一预览镜头。

### 动作画面重制

在「动作与关键帧」选择一个动作，打开「动作画面重制」。先建立画面计划，填写整组要求及各画面的姿势、时间和表情，再通过当前图片服务生成；同组最多 3 张并发。每张候选分别确认角色、表情、肢体与服装、尺度、握持，单张重试保留其他已确认画面。

原画使用统一画布和角色物理尺度。跑步循环使用跑姿首帧作为回接目标；非循环动作按计划回到基准或保持战败终态。倒地高度降低不能触发按人物高度重新放大。已接受的 idle 与基础部件保持原样。

全部原画审阅后，分析各帧关节坐标、可见部件多边形与前后顺序。坐标候选需单独载入与审阅，可修改关节和轮廓顶点；隐藏部件明确标记不可见。程序将原画像素分配给独立透明裁片，并检查来源指纹、缺漏和重组误差。无法覆盖的像素需要修正轮廓，不能用整个人物图片作为一个身体部件跳过。

「检查轮廓缺口」显示未覆盖像素及其范围。对于有限的接缝，可以明确生成邻近实体部件的归属候选：仅处理原来没有归属的可见像素，保留已有归属，排除眼眉嘴等表情附件，距离最多 64 像素，主体缺口比例不得超过 15%。逐项检查受影响部件的彩色归属和新增区域后才能接受；接受后仍须重新确认该帧坐标。这里的补归属是可审阅的推定，不是精确语义分割或隐藏面补绘。未解决的主体缺口仍会阻止应用。源图、轮廓或关节变化会使旧候选失效。

共享基准图可选择复用已校准的整套轮廓与前后顺序，仍须检查重组；不能只复用旧轮廓而混入新猜测的层级。

「应用选定动作并查看 Spine 预览」生成真实的骨骼定位、部件附件切换和绘制顺序，只替换该动作。这里采用逐帧切换，适合确认大幅姿态的画面；当前裁片记录为原画可见区域，没有补画隐藏面，也不代表已经完成连续骨骼补间。连续变形与平滑过渡需要另外制作和检查。

原画、分片、审阅、坐标及来源分别保存在作者工程中，运行时、可编辑和 Unity 资源包均保留回导信息。动作图候选与基础逻辑部件分开保存。正式保存前，已建立的动作画面计划必须完成检查并应用，避免将候选误当成当前播放的动作。

导入与导出统一限制为最多 4096 个文件，压缩包及解压后文件总量均不得超过 256 MiB。可编辑备份包含原始工程副本，文件数和总量按实际打包结果计算；超限会在导出前提示。

### 表情与附件变体

在拆分或绑定步骤使用「部件显示组」，将左右眼、左右眉毛、嘴型分别入组，或创建自定义组以管理手型和其他细节。同组共享骨骼和遮挡层级，默认只显示指定附件。用「复制为新变体」沿用矩形与绑定，重新补绘独立图片；副本不会被算作已完成。「预览此附件」用于临时检查，不更改默认表情。离组或删除部件会清理相关默认项与关键帧引用。

在动作关键帧中，为每个显示组选择具体附件、隐藏或沿用前一帧。AI 动作规划只选择已有变体，可设计眨眼、咏唱、受伤与胜利表情；循环动作要求首尾附件相同。导出时同组对应一个 Spine slot、多个 skin attachments，并写入离散 attachment timeline，所有变体 PNG 与本地作者数据均保留。

## 完整部件与连续动作

在「拆分与补绘」打开「审阅完整重叠部件」。两侧以相同坐标显示完整底图及原图轮廓，逐件确认隐藏接头、独立内容和可见轮廓归属；脸底还须确认无眼、眉、嘴且皮肤完整。全部确认后计算真实重组候选，查看轮廓、颜色与隐藏像素差异，再明确应用。应用保留关节、权重及动作，可撤销。指纹同时锁定源图、几何和每件底图，修改图片、轮廓或位置后需要重新审阅。

完整模式保留隐藏支持，不用源图排他归属裁掉底面。逐件「可见像素来源」可选择保留已审原图像素或仅使用完整独立底图；原图始终用于核对位置和比例。脸底及独立五官固定使用各自底图，避免把旧皮肤或五官重新粘回。改变选择需要重新确认当前件，策略随工程导出保存。设置姿态的像素差异会如实显示；交并比高不等于隐藏面、接缝或连续动作已通过。

动作画面窗口的「动作画面用途」可选择「关键姿势参考 · 连续骨骼动画」或原画切片。参考模式保留原画、坐标、审阅和来源，清理可重新生成的逐帧纹理；播放、保存和 Atlas 使用骨骼与网格动画。切回原画切片后需重新检查并明确应用，不能把稀疏附件切换称为连续补间。

连续规划把立绘作为图一，随后最多附四张当前动作已审阅的关键图。每张必须通过形象、表情、肢体、尺寸及握持检查，并核对真实图片指纹和画布尺寸；拒绝或不匹配的画面不会送入规划，任务记录保留排除原因。参考图只指导姿势、节奏和遮挡，当前骨架与完整部件决定头部、四肢及法杖的物理尺寸。没有可用参考图时仍可按立绘和文字规划，界面不会声称使用了动作图。

局部位移沿父骨坐标轴，缺失时为零；局部缩放缺失时为一，默认等比。位置、角度和缩放连续插值，绘制顺序及表情附件在关键帧离散切换。当前双骨脚锁与副手握持支持等比缩放；受约束骨链或祖先的非均匀缩放会明确报错。前后顺序按部件插槽调整，同组附件只显示一个变体。

在部件、绑定或动作页展开「部件出现时间与网格位置」，选择部件即可看到各动作的显示时段和隐藏时段。网格每格 32 像素，行列从 1 开始，位置按当前部件框中心计算；列表列出区间起点，运动中位置会继续改变。「在网格中定位」暂停到对应动作和时刻，直接显示所选部件框、中心坐标和所在格。该操作只查看，不改变部件或关键帧。骨骼、尺寸及层级等信息收在详情中。

## 数据与恢复

骨架草稿保存在共享本机 SQLite 工作区的独立 `ispine-rig-drafts` 分区中，保留原 IndexedDB 作为迁移来源。仅导入立绘、尚未分析结构的草稿也可恢复；未操作的空白入口不会产生草稿或资源。返回资源页和普通导航会等待当前草稿保存；浏览器刷新或关闭遵循下述离页保护。AI 任务在本机服务中独立保存，切走后可重新打开查看和应用；重启后被中断的任务明确显示失败，已完成候选保留，不会自动重新提交。

草稿页显示等待、保存中、已保存或失败，只有本机数据库事务完成才显示已保存。修改按编辑会话串行写入；离开旧页面后的延迟回调不能写进新角色。失败内容保留以便重试，普通导航会等待排空待写内容。页面转入后台时提前尝试保存；刷新或关闭时若仍有未提交内容，会请求浏览器离开确认。浏览器不能在卸载期间保证异步写入完成，应等待「已保存到本机」后刷新。

普通编辑器仅重新捕获动画缩略图时，不改变资源版本。名称、源文件、部件替换与校准、生成引用等实际内容改变才产生新版本；同一时刻连续修改也获得不同版本。进入骨架页不会因预览帧变化将仍匹配的逐帧动作草稿分离；真正的资源版本冲突仍保留旧草稿并要求另存。

导出或重新进入骨架页时，按 Atlas 页读取当前图片，再逐个核对基础部件与动作区域。即使没有普通校准记录，也会带入外部修改过的贴图；不会直接沿用过期作者图片。多部件共享同一页的读取结果，并依次释放临时图片，减少大贴图工程的重复解码与内存占用。

每份已保存资源独立关联草稿；同一工程导入为多个资源时，草稿互不覆盖。继续旧草稿时会比较原资源版本，原资源已校准、更新或删除则提示另存为新资源。保存同时检查版本，保存中断后重试沿用已创建的资源，避免重复创建或覆盖其他窗口的修改。

从资源的「骨架与动作」重新进入时，同版本且归属一致会直接恢复草稿；版本或归属冲突则先独立保留旧草稿，再打开当前资源及最新校准。旧草稿保留失败时停止进入，避免自动保存覆盖尚未取回的修改。

保存为正常资源时，会保存 Spine JSON、Atlas、打包贴图、`images/` 下各独立 PNG，以及 `.ispine/rig/` 中的作者文档与立绘。原始参考独立保存为 `appearance-reference.ext`，保留导入文件原字节；最终 Q 版图保存为 `source.png`。生成说明、服务、模型和任务来源保存在作者文档中，图片采用本地文件引用，不依赖临时网址。原始参考文件指纹与生成请求中规范化 PNG 的指纹分别记录。普通部件校准会在重新打开骨架前带入当前图片效果；运行时导出后回导也不会把外观恢复成旧作者图。

结构和动作规划明确使用当前本机 Codex 账号，不读取或复制账号凭据。Q 版形象与部件补绘使用「AI 连接」中选定的图片服务；API Key 图片适配器不会被假定具备骨架规划能力，失败时不自动切换服务。形象候选验证实际透明通道，并保持比例置入 1024×1024 透明画布；迟到的旧来源结果不能覆盖新立绘。密钥不会进入骨架文档或资源包。

## 计算与检查

作者文档使用立绘像素坐标。编译时计算父子局部变换、骨长与旋转中心，转换为 Spine 向上的 Y 轴。网格顶点保留原始拼接位置，影响骨权重归一化；调整关节不会把设置姿态中的图片整体移开。

动作先按关键姿势插值，再求解脚锁与双手握点，最后以 30 fps 烘焙为 Spine 骨骼关键帧；附件切换保持离散时间。脚锁使用双骨腿链，副手根据武器当前姿态求解双骨手臂；不可达目标不会通过拉长骨骼伪装为成功。界面报告属于骨架文档 FK 采样，默认误差门槛为 0.5 像素，循环角度门槛为 0.5 度，并列出左右脚实际启用约束的采样数。未接触时的 0 误差不代表完整脚滑验收。官方运行库中的实际烘焙误差由专项测试单独验证。

脚锁启用与释放属于离散边界。导出在边界前后保留独立采样，避免普通插值提前混入解锁姿态；动作设计仍需让首个解锁姿势接近释放前的求解姿势，避免脚掌或膝盖在释放瞬间跳变。

第一版支持 Q 版人形、刚性部件和规则加权网格；网格自由顶点拓扑、完整曲线图编辑器和非人形骨架不在当前编辑范围。AI 补绘、关节识别和动作节奏仍需要在预览中检查；数值检查不代表画面已通过美术验收。

## Spine 编辑器与导出

导出使用 Spine 4.3 JSON 格式，保留骨骼、绑定、动作、Atlas 和贴图。独立 PNG 放在 `images/`，JSON 的 `skeleton.images` 指向该目录，便于官方编辑器通过 Import Data 导入后继续编辑并保存为 `.spine`。iSpine 自身不直接生成 `.spine` 二进制源工程。官方说明：[导入数据](https://en.esotericsoftware.com/spine-import)、[JSON 数据格式](https://en.esotericsoftware.com/spine-json-format)。

新骨架及动作画面的附件按原分辨率打包，超出单页容量时生成 `rig.png`、`rig-2.png` 等多页贴图，每页边长不超过 8192 像素。运行时、可编辑和 Unity 导出均保留全部页与独立 PNG；单个部件含边距仍超过单页上限时明确拒绝，不缩小图片。

自动检查覆盖实际官方运行库的关节和加权顶点、脚锁、双手挥棍、动作单独替换、异常数据、资源与作者文档往返、校准回灌、草稿事务、真实服务路由与任务取消。真实账号与桌面验收的记录见 [验收记录](validation.md)。
