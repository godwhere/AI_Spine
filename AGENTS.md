# Prototype Instructions

## Workbench scope

- The software's public name is `iSpine`. Keep the existing profile directory, IndexedDB name, archive metadata paths, and application bundle ID stable so existing projects remain available.
- Resource deletion moves the selected project into a persistent trash view with restoration. Preserve source files, replacements, calibration, and generation references; reject stale autosaves for trashed projects and do not seed new examples when the active library is empty but trash contains projects.
- Trash supports permanent deletion and clearing after an explicit in-app confirmation. Remove character data, retain only ID tombstones to reject stale saves, and keep an intentionally emptied library empty. Keep separately exported files and independent generation history outside this operation.
- Creating from a template opens a temporary draft. Previewing animations or opening/closing AI creation must not add an unchanged template copy to the resource library. Persist a new template draft only after meaningful authored content (edits, an applied reference, written brief or rename), an explicit save, or export. Imports and existing saved resources retain normal persistence; undoing edits must not discard an already saved resource.

- Give iSpine its own desktop resource and editor layout, informed by mature open-source creative tools. Preserve the template/calibration/export workflow; do not reproduce the earlier reference website's layout.
- The selected UI target is the third displayed 2026-10-20 design: a light resource explorer with violet accents, horizontal top navigation, compact rows at left, a large central animation preview, and a narrow right inspector. Use actual template art and region counts. Preserve list/grid search, trash, AI setup and editor workflows, with dedicated list/preview navigation on narrow screens.
- Keep template type/category controls directly above the library. Template display has only two choices: the unchanged one-column list and fixed three-column pictures in a compact left pane, with a large full-height center preview and separate right inspector. Do not expand the gallery across most of the workspace or stack a small preview above details. No two- or five-column template mode. Preserve selection, search, categories, real animation, accessible labels, and square non-overlapping rows. Resource-library list/grid modes are independent.
- Saved resources can become independent local templates, with baked replacement/calibration results, explicit name/type/categories, and a permanent "我创建的" filter. Updating from the same resource replaces the same template instead of creating duplicates. Cancelling must not save. Original/derived resources and template snapshots have independent lifetimes; only custom templates can be removed. Keep template data in its own IndexedDB database without changing the existing project database.
- Complete local template import, part replacement and calibration, real Spine animation playback, and export/re-import verification before AI generation.
- Do not implement credits, membership, payments, or billing.
- Keep user-imported assets local. Preserve skeleton animation, mesh, skin, and constraint data on export.
- The independent rig workflow starts from a Q-version humanoid illustration, never an existing template skeleton. AI proposes geometry/occlusion and motion poses; deterministic code calculates transforms, mesh weights, IK, atlas packing, and validates output. Preserve both AI and procedural provenance; a source crop or placeholder is never completed inpainting.
- Detailed rigs support independently animated hands, forearms, hair, clothing and equipment rather than a fixed 18-part limit. Preserve native generated PNGs, aspect ratio, immutable candidate mapping and unfinished-part retries. Eyes, brows, mouths, hand shapes and other details can be added as mutually exclusive attachment variants with defaults and discrete keyframe switches; export and re-import must preserve their Spine slots, attachments and timelines. Distinguish texture-region counts from joint counts.
- Preserve the approved character's silhouette and proportions when splitting parts. Use a shared source-pixel coordinate grid and explicit part masks; lock visible source pixels and use generated art for hidden surfaces. Show source-versus-assembly comparison and real coverage/error measurements. Do not squeeze independently redrawn art into inaccurate rectangles, or treat a high part count as proof of fidelity.
- For action-image remakes, approve complete key images before deriving per-frame visible regions, joint landmarks, pivots and draw order. Preserve an already accepted idle and the original base artwork. Hurt and defeat require visually painful or exhausted expressions; attachment names and numeric switching checks do not prove the expression is correct. Use the supplied action image as the visual target for the actual exported Spine result.
- Keep per-frame action regions separate from base logical parts. Explicit stepped-part playback may use source-visible regions, with honest provenance and unfinished hidden surfaces; it must not be presented as completed hidden inpainting or smooth skeletal deformation. Never pass a whole-character image off as independently split body parts. Large turns and defeat poses need supported artwork/variants rather than forcing the standing image through extreme rotations.
